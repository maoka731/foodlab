# FoodLab 2.0｜產品架構與 Claude Code 開發規格書

版本：v1.0｜2026-11-03｜狀態：規劃草案，待程式碼盤點後確認

## 0. 給 Claude Code 的執行總指令

你正在維護一個**已存在**的 FoodLab 網站。請先讀取專案原始碼、路由、資料結構、目前遊戲流程及 UI 樣式，再提出差異分析與分階段實作計畫。**禁止直接重建整站、覆蓋現有設計或一次實作所有功能。** 每個階段先列出預計修改的檔案、資料遷移風險與驗收方式，待確認後才開始實作。若本文件與現有實作衝突，先回報差異，不要擅自刪除既有功能。優先保留原有文青雜誌視覺、食材圖像、料理圖片、互動動畫與食譜資料。

產品不是教做菜的食譜網站，而是讓小資族透過輕鬆料理遊戲，理解食材營養、菜色搭配與外食選擇的**遊戲化營養探索網站**。避免將烹調技術、完整料理教學或實際下廚轉化率當作主要成功指標。

## 1. 產品策略

### 1.1 定位
- 名稱：FoodLab 食驗室
- 核心主張：**把營養知識變成一場好玩的料理探索。**
- TA：以小資族、外食族為主；想輕鬆玩、蒐集卡片、順便理解食物營養與餐食搭配的人。
- 主要使用情境：通勤或休息時短時間遊玩；用餐前想知道菜色與營養搭配；從圖鑑取得外食靈感。
- 不以實際烹飪、食材採買、精準熱量控制、醫療營養建議為核心。

### 1.2 產品目標
1. 使用者在 30–90 秒內完成一次探索，取得可理解的營養收穫。
2. 小遊戲有趣且可略過，不阻礙營養資訊取得。
3. 料理營養卡可收藏、比較與用於餐盤搭配挑戰。
4. 主題扭蛋創造驚喜與回訪理由，但不能成為取得基本營養知識的唯一門檻。

### 1.3 核心循環
選擇模式 → 選擇食材或營養主題 → 短小遊戲（可跳過） → 料理結果與營養知識 → 獲得食驗幣／解鎖卡 → 主題扭蛋或圖鑑 → 用卡牌挑戰餐食搭配 → 回到探索。

## 2. 使用者模式與導航

### 2.1 雙模式
**跟著玩（引導式）**：選擇料理、食材或主題，系統提示可解鎖的菜色，透過輕鬆小遊戲完成探索。適合想快速得到營養靈感的玩家。

**自由實驗（探索式）**：任意選擇食材，查看可搭配的菜色及差一項食材的建議；可選擇短遊戲，探索未知料理。不要把不相容食材全部禁用。無法匹配時顯示有趣的實驗結果及替代建議，**不能捏造營養資訊或不存在的菜譜**。

兩模式共用食材資料、料理卡、遊戲、獎勵、圖鑑與進度紀錄；不要複製兩套邏輯。

### 2.2 建議資訊架構
- 首頁：品牌主視覺、兩種模式 CTA、本週主題、今日探索靈感、近期解鎖。
- 食驗廚房：食材選擇、相容菜色提示、進入小遊戲或快速查看。
- 料理營養卡／圖鑑：已解鎖與未解鎖、主題分類、收藏、營養亮點、餐食搭配。
- 扭蛋研究所：主題卡池、食驗幣、抽卡動畫、重複卡處理、機率說明。
- 餐盤搭配挑戰：以已獲得或公開示範的料理卡完成情境挑戰。

MVP 導航避免超過 4–5 個主入口；扭蛋及圖鑑可整合為「收藏室」。

## 3. 核心功能規格

### F01 食材探索與菜色配對（P0）
- 顯示食材圖片、名稱、1–2 個營養標籤、短知識。
- 選擇食材後即時顯示：可解鎖菜色、尚缺一項食材的菜色、相關營養提示。
- 引導模式優先顯示可完成的組合；自由模式允許自由選擇，不因無相容食譜而鎖住所有食材。
- 使用明確的資料庫配對規則，不依食材名稱字串臨時猜測。
- 空狀態：沒有可配對料理時，提供替代食材或不同主題，而不是錯誤頁。

### F02 料理小遊戲（P0，先沿用既有玩法）
**存在目的**：增加互動樂趣、提供適量獎勵、讓營養概念被主動注意到；不是模擬精準烹飪。
- 保留既有切菜／炒菜／調味等已實作互動，先評估可重用程度。
- 第一輪只選 1–2 個核心小遊戲優化手感，不新增大量遊戲。
- 目標單局 30–60 秒；支援鍵盤／滑鼠／觸控基本操作，減少反覆等待動畫。
- 設計 Perfect、Combo、趣味音效與動畫回饋，但不將營養價值與玩家手速連動。
- 可選「快速探索」直接看料理卡；首度快速探索可取得基本卡片，遊戲則提供額外食驗幣。不得用遊戲阻斷必要營養資訊。
- 可插入 1 次輕量營養判斷，例如在不同食材中挑選膳食纖維來源；答錯給友善回饋與正確資訊，不強制考試。
- 遊戲失誤不造成永久損失或無法取得卡片。

### F03 食驗幣與獎勵（P1）
- 遊戲完成獲幣，表現可有少量加成；營養搭配挑戰完成也可獲幣。
- 建議初始平衡（可調整）：完成探索 +20 幣、完成遊戲 +30 幣、每日首次探索 +20 幣、扭蛋 100 幣／抽。
- 以上僅為**測試參數**，需依遊玩時間與測試調整。
- 防刷：相同動作連續觸發不能重複發獎；使用 event ID 與交易紀錄防重。
- MVP 無付費、無現金兌換、無轉售，不引入付費抽卡。

### F04 主題扭蛋（P1）
- 卡池按**生活情境／營養探索主題**分類，非單純菜系。
- 初期主題：①百元便當研究所 ②超商生存指南 ③彩虹營養收藏冊。
- 每個卡池有封面、介紹、可獲得卡片清單、明確機率與抽卡成本。
- 抽到卡片後顯示料理名稱、營養亮點、適合的外食搭配，以及收藏入口。
- 重複卡：先採轉換為少量食驗幣或碎片；**不得獎勵超過抽卡成本**造成無限循環。
- 設計保底或未持有卡優先規則，避免重複卡造成挫折。初期建議「每 5 抽至少一張未持有卡（若卡池仍有未持有卡）」作為待測規則。
- 稀有度只表示收藏難度或特殊設計，**不代表營養優劣**。
- 卡池可抽到未探索的料理卡；基本營養知識仍可從食材頁及公開內容取得。
- 抽卡結果必須持久化，不能重新整理就遺失；不要只用前端 Math.random 假裝有公平性／防作弊保障。若純前端 MVP，明確標記為單機娛樂、無帳號競爭與無金錢價值。

### F05 料理營養卡（P0，最高優先）
**不是完整食譜教學卡。** 每張卡的目標是回答：「有哪些食材？主要營養特色是什麼？外食時可以怎麼搭配？」

卡片分三層：
1. 正面：料理圖片、名稱、食材標籤、2–3 個主要營養亮點、主題／收藏狀態。
2. 詳情：各食材貢獻的營養特色、可理解的說明、常見搭配優勢與限制。
3. 生活應用：「這道菜還缺什麼？」、「搭配什麼更完整？」、「外食選擇小提醒」。

可選的營養數值：若有可信來源與標準份量，才顯示每份熱量及三大營養素，需標示份量、估算方式及資料來源；若無可信定量資料，先用定性標籤，不能憑料理名稱產生假精確數值。

營養標籤需避免療效語言（如「降血壓」「排毒」「燃脂」）與絕對化健康評分。料理中的蛋白質、蔬菜、主食比例須以實際食材及份量判斷，不能只靠菜名推斷。菜色搭配建議要承認個人需求差異。

### F06 圖鑑與收藏（P1）
- 分開「已發現／已持有／已收藏」三種狀態，避免資料意義混淆。
- 未解鎖卡顯示輪廓與線索；營養基礎資訊不應全部隱藏。
- 已解鎖卡可再次查看營養知識、外食建議與搭配玩法。
- 支援主題進度、卡片篩選與排序；先不做社交分享及排行。

### F07 餐盤搭配挑戰（P1／P2）
- 以已解鎖料理卡（或系統提供的示範卡）組成一餐。
- 題目情境例：便利商店午餐、便當店選菜、今天想增加蔬菜攝取。
- 判斷食物類別與餐食組合，提供「已涵蓋／建議補充」的回饋；避免只有對錯二分。
- MVP 先以食物類別判斷，**不可宣稱餐盤營養已達標**；若要評估份量或鈉含量，需有實際數據。
- 完成挑戰可獲食驗幣與主題圖鑑進度。

## 5. UI／UX 指引
- **沿用現有** FoodLab 文青雜誌風格、暖色系、食材插畫與料理圖片；不要突然改成霓虹賭場、重度 RPG 或通用 SaaS 後台。
- 扭蛋可使用復古雜貨店／料理研究室風格；動畫短、可跳過、支援 reduced motion。
- 遊戲回饋輕鬆幽默、不羞辱食物、不把高熱量食物妖魔化。
- 營養卡優先易讀、可掃讀；「食材來源→營養亮點→外食搭配」形成固定閱讀節奏。
- 行動裝置優先：觸控目標、載入速度、抽卡動畫及卡片閱讀都需驗證。
- 不強制登入，不以每日連續登入懲罰使用者。

## 6. MVP 範圍與開發階段

### Phase 0｜程式碼盤點（必做，禁止直接改碼）
- 列出路由、元件、資料來源、現有小遊戲流程、營養卡現況、圖片資產及儲存方式。
- 對照本 PRD，標示「可沿用／需修改／需新增／有風險」。
- 提供修改檔案清單、開發順序與粗估工時，等待確認。

### Phase 1｜核心營養價值（P0）
- 食材營養標籤、菜色配對提示。
- 重構料理營養卡：食材來源、營養亮點、外食搭配。
- 保留既有遊戲，加入快速探索入口。
- 驗收：不用玩遊戲也能取得可靠營養資訊；選食材能看到相關菜色。

### Phase 2｜遊戲與獎勵（P0–P1）
- 優化 1–2 種現有小遊戲的節奏、回饋與完成體驗。
- 食驗幣與事件去重、遊戲完成獎勵。
- 驗收：完成遊戲獎勵正確、重整不重複領取、可跳過動畫。

### Phase 3｜圖鑑與主題扭蛋（P1）
- 圖鑑狀態、收藏、3 個主題卡池、重複卡與保底規則。
- 驗收：抽卡扣幣／入庫一致，抽卡機率透明，重整後進度保留。

### Phase 4｜餐盤搭配挑戰（P1–P2）
- 先做 3 種生活情境，料理卡組合、回饋、完成獎勵。
- 驗收：有明確的搭配判斷依據，不做缺乏數據的精準健康宣稱。

### 明確不在首版範圍
- 完整烹飪教學、採買清單、冰箱庫存管理、個人化醫療飲食建議。
- 付費抽卡、會員排行、交易、社群與多人功能。
- 無限制 AI 生成料理或無根據的營養數值。

## 7. 驗收與產品指標

### 功能驗收
1. 原有首頁、食材圖、料理遊戲與菜譜正常顯示，無主要流程退化。
2. 引導／自由兩模式可完成「選食材→料理營養卡」。
3. 食材配對結果符合資料規則，無結果時有可理解的提示。
4. 遊戲可完成／可略過；營養資訊不被鎖住。
5. 食驗幣與扭蛋抽卡有持久化、重複事件防護與明確補償。
6. 營養卡有營養來源、合理搭配提醒；缺乏數據時不顯示虛構數值。
7. 行動裝置可用，支援基本無障礙與 reduced motion。

### 產品觀測
- 首次探索完成率、單次造訪探索次數。
- 料理營養卡詳情開啟率、營養提示互動率。
- 抽卡後圖鑑瀏覽率、重複卡比例。
- 餐盤搭配挑戰完成率、7 日回訪率。
- 透過簡短題目測試「能否說出食材的營養特色及合理搭配」，避免只看點擊率。

## 8. 營養內容品質規範
- 每個營養主張保留資料來源與審核狀態（建議台灣食品營養成分資料庫及可信公共衛生資料）。
- 對維生素 C 等受烹調影響的營養素，不直接假設成品與生鮮含量相同。
- 外食搭配採教育性、一般性語氣；避免疾病治療或個人化醫療結論。
- 「均衡」不是單一道菜的固定屬性，而是整餐、全天及份量的綜合結果。
- 使用者選擇高油、高糖或高鈉食物時，以搭配與頻率提醒為主，不使用羞辱或負面標籤。
